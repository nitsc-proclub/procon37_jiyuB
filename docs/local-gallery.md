# 科学館展示用のローカルギャラリー

通常版のローカルサーバーを起動し、`http://localhost:3000/gallery` を開く。別ポートで起動している場合は、そのポートの `/gallery` を使う。既存の「デモ記録」画面にある「展示ギャラリーを開く」からも開ける。

```powershell
npm.cmd run dev
```

## 表示と操作

- PC横画面では4列×2段、約8作品を表示。完成した絵とタイトルだけを表示する。
- 同じローカルサーバーのデモ記録を新しい順に表示する。音声のない作品はギャラリーから除外し、元の記録は残す。
- マウスでスクロールすると古い作品も閲覧できる。作品を選ぶと、既存の描画アニメーション・カラオケ歌詞の部品で自動再生する。
- 再生画面の「一覧にもどる」は常時表示。再生終了から5秒後にも、選択作品と閲覧位置を保って一覧に戻る。再生し直す／歌詞や音声バーでシークすると、終了後の待機は解除される。
- ブラウザーが音声の自動開始を止めた場合は「歌を再生する」を表示する。
- カードの揺れ・位置・傾きは作品IDから決定する。1920×1080を基準に上下6〜12px、6〜11秒の周期で、選択中の作品も浮遊する。画面付近の行だけを描画し、大量の記録があっても画像やアニメーションを一度に読み込まない。

## 放置時と新作の到着

- 25秒間操作がなければ展示モードへ移行。画面1枚分を約90秒でゆっくりスクロールする。
- 巡回対象は最新32作品。終点で3秒留まり、背景色の短いフェードを挟んで先頭へ戻る。手動閲覧では32件より前の作品も見られる。
- マウス移動・クリック・ホイール・キー操作で自動巡回を停止する。音楽の自動選択・自動再生は行わない。
- 作品の画像・音声・メタデータの保存完了後、`/api/demo-records/events` のSSE通知を受けて一覧を更新する。
- 放置中に新作が届いたら先頭に戻して仲間入りを見せる。操作中・再生中は割り込まず、先頭を表示したときに演出する。連続保存時には先頭画面の作品を優先し、演出待ちは最大8件に抑える。
- 接続が戻ったときの再取得と30秒ごとの照合も行う。フォルダーへ直接追加された記録も次の照合で反映される。接続エラー時は表示済みの作品を維持する。
- 展示ギャラリーはOSの「視覚効果を減らす」設定にかかわらず、浮遊・仲間入りの演出・自動巡回を行う。OS設定自体や、通常のメーカー画面の設定は変更しない。

## 片手デバイス

添付デバイスの割り当てに対応。右回しでRight、左回しでLeftを送る。設定は `gallery/model.ts` の `GALLERY_KEY_BINDINGS` にまとめている。

| アクション | キー | 動作 |
| --- | --- | --- |
| `next` / `previous` | → / ← | 新しい順の並びに沿って選択を進める／戻す。端では止まり、必要に応じて画面をスクロールする |
| `confirm` | Enter | 選択作品を再生。再生中は一時停止／再開 |
| `back` | Esc | 一覧へ戻る |
| `refresh` | R | ページを壊さず記録一覧を再取得 |
| `volumeUp` / `volumeDown` | 割り当てなし | 音量を5%ずつ変更。設定は同じブラウザーに保存 |
| `togglePlayback` | Space | 再生中の一時停止／再開。一覧では何もしない |

Ctrl・Alt・Shift・Windows/Commandを押した組み合わせや、文字入力・IME変換中は上記の操作を実行しない。矢印キーは連続入力でき、Enter・Spaceなどの長押しによる再実行は抑止する。Tab・Shift+Tabでのフォーカス移動も利用可能。

ロータリーの重複入力対策として、同じ方向の入力は最初の1回をすぐ反映し、その後180ms以内の入力をまとめて無視する（キー入力・カスタムイベント共通）。無視した入力を後から実行することはない。連続回転・矢印長押しは約180msごとに進み、逆方向への切り替えは待たずに反映する。調整値は `GALLERY_SETTINGS.navigationIntervalMs`。必ず2入力を1移動にする方式ではないため、単発入力でも進む。

選択作品が画面から外れる行へ移ると、約360msで滑らかにスクロールする。行全体が見える位置を基準にするため、同じ行でカードの高さの揺らぎによる上下移動は起こさない。続けて回すと現在位置から最新の選択へ向かい、ホイール・クリック・タッチ・マウス移動で中断する。OSの視覚効果設定には依存しない。所要時間は `GALLERY_SETTINGS.selectionScrollMs`。

入力処理は `window` の `ekaki-gallery-action` カスタムイベント（`detail` に上記のアクション名）でも呼び出せる。キー割り当てとは分離している。

## 公開版との境界

ギャラリーは `import.meta.env.DEV` とローカル機能フラグを満たす場合だけ読み込む。`npm run build` で作る公開用ファイルにはギャラリーの画面・CSS・リンク・SSE購読処理を含めない。公開環境では `/gallery` を提供しない（現在のWorker Static Assets設定では404）。

記録APIとSSEはViteのローカルmiddlewareにのみ存在し、Cloudflare Workerには追加しない。ビルド済みの `preview` では展示画面を提供しないため、展示には上記の `dev` を使う。既存の合奏ブランチとは独立した機能。

## 確認

```powershell
npm.cmd run test:gallery
npm.cmd run type-check
npm.cmd test
npm.cmd run build
npm.cmd run check:gallery-public
```

`test:gallery` は並び順・選択保持・配置の画面内収まり・最新32件の巡回範囲・描画タイミング・保存完了通知・SSE再接続／終了を検証する。`check:gallery-public` は公開ビルドにギャラリーの特徴的なコードやCSSが残っていないことを検証する。

実機では投影解像度・会場での音量・デバイスのキー割り当てを合わせる。ギャラリーと作品生成画面は同じ保存先を使うローカルサーバーで開く。
