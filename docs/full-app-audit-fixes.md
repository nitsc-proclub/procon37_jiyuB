# 全体レビューで確認した不具合の修正（2026-09-22）

## 修正した動作

1. ローカル記録APIは単一の名前だけを受け付け、ドット、区切り文字、不正なURLエンコード、リンク経由の参照を拒否する。記録ルート自体を削除できない。ブラウザからの別Originの読み書きも拒否し、同一OriginのLAN利用は維持する。
2. ブラウザ保存作品への描き足し・元に戻す操作で、元の絵を消さない。編集中は画像URLを維持し、新規作成・別作品への切替時に解放する。
3. 画面を移動しても、編集中の線とundo/redo履歴をApp内で維持する。明示的な全消去・新しい歌では初期化する。ページ再読み込みをまたぐ自動保存ではない。
4. 現在の候補IDを含むZIPを読み込める。candidate-a、candidate-b、候補IDなしの旧形式を受け付け、未知のIDや項目は拒否する。
5. 明示したみらいサーバー（VPC）を混雑時も維持する。「自動」は従来どおりCloud Runへ振り分け、実際に使った接続先を表示する。認証済み音声レスポンスにも接続先を付ける。
6. 作品と評価回答を同一トランザクションで保存・削除する。削除後に回答更新や音声準備が完了しても復活させない。回答の容量も100 MiBの上限へ含める。
7. ローカル記録にアニメーション用の無音WAVを歌声として保存しない。再表示時は楽譜から再生時計を作り直す。旧記録はアプリ固有の無音PCM形式と全ゼロの内容が一致した場合だけ音声なしとして扱い、ファイル自体は変更しない。

## ブラウザ保存の移行

`cho-ekaki-uta-debug-history` はバージョン4となり、作品に紐づく `evaluationDrafts` を持つ。旧回答DBはバージョン2へ更新して旧版の再書き込みを防ぎ、歌詞内容と生成時刻が対応する作品へ回答を移した後、旧コピーと孤立した回答を除去する。作品・お気に入り・生成数は維持する。

旧版のタブが移行を妨げる場合は、他のタブを閉じる案内を表示する。保存済み作品を削除して回避しない。新旧DB間のコピーは再実行できるため、途中で終了しても次回に継続する。

初回保存が完了する前の回答更新は保存待ちに接続する。音声の後着更新は作品の存在を確認し、新しい回答を古いスナップショットで上書きしない。未保存・削除済みの作品への回答保存は成功と表示しない。
