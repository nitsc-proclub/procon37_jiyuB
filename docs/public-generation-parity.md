# 公開生成の暫定仕様（2026-09-22）

## 通常設定

公開Workerとstagingは `LYRICS_PIPELINE_MODE=legacy` で画像・線の要約から1段生成する。通常は1候補。モデル優先順はローカル設定と同じ `gemini-3.8-flash, gemini-3.7-flash, gemini-3.6-flash, gemini-3.5-flash, gemini-3.1-flash-lite, gemini-2.5-flash-lite`。通常の成功時に画像解析用・作詞用の2回の生成依頼は行わない。サービスエラー時のモデル切替と、容量不足時の短縮再生成は例外として残す。

ブラウザの `VITE_GEMINI_IMAGE_MAX_DIMENSION=768` により、長辺が768pxを超える画像を白背景・長辺768px以下・JPEG品質0.82へ縮小する。小さい画像、変換不能な画像は元の画像を使う。署名・クラウド保管の対象は、AIへ実際に送った同一の画像バイト列。線の座標やローカル表示の元画像は縮小しない。公開保存APIはJPEG・PNG・WebPを受け付ける。

## 歌詞確定から歌声まで

1. `generateSingableLyrics` が全候補を実際に楽譜化して検査する。公開 `SINGING_BPM=125` とブラウザ `VITE_SINGING_BPM=125` を揃える。1行8拍/32単位の制約はBPMを下げても増えない。
2. 容量不足のときだけ12モーラ以内、次に8モーラ以内で短縮依頼する。初回＋最大2回。2段生成では画像解析を使い回す。上限後も収まらなければ説明付き422を返し、チケットは発行しない。
3. Turnstileに通った生成処理内で、VPCのVOICEVOX `/accent_phrases?speaker=3` を歌唱かな行ごとに取得する。同じ行は同じリクエスト内で再利用。全候補で約6秒、1回の接続待ちは最大1.5秒、応答は64KiBまで。応答本文の待ちにも上限を設ける。追加の公開解析APIは作らない。
4. ローカルと共通の `voicevoxAccentAlignment` でモーラ照合し、音高・句末位置のヒントを返す。不一致・タイムアウト・異常応答・VPC未設定ならそのヒントを省いて続行する。解析だけのためにCloud Runは起動しない。`VOICEVOX_ACCENT_ENABLED=false` で解析を停止できる。
5. ブラウザの共通楽譜処理が拍・長音を維持し、句内の不自然な伸ばしを局所補正。その最後に終止ドを直前音以上に調整する。調整不能なら元の有効な配分で続行。曲の前後に各2フレームの合成用休符を加え、各歌詞行の長さは変えない。
6. 最終歌詞から候補単位の音声grant、待ち行列capability、評価receipt、画像・線・歌詞に結び付いた保存ticketを発行する。通常の公開歌声は1候補でも待ち行列を通り、一時音声を取得する。既存のVPC/Cloud Run振分け・再取得期限を使用する。

## 保存と評価

2026-09-22の追加指示で、新規クラウド保存は暫定停止した。現在のフラグ・文言・ギャラリー・回数は [公開・ローカルの保存と表示](public-local-experience.md) を参照。以下のクラウド形式は、保持している実装と再開時の仕様を示す。

1段生成も `candidate-a` を持つ共通応答（`pipelineMode: single`）を返す。実行していない画像解析は `drawingAnalysis: null` / モデル名 `not-run` として記録する。架空の分析結果は作らない。

1候補では比較画面を出さず、`firstImpressionSelection: null`・`alternativePreviewed: false` のまま保存する。保存同意画面は実際の候補数に合わせて説明する。現在の承諾時はブラウザだけに保存し、拒否時は作品を長期保存しない。クラウド再開時には非公開のD1/R2保存にも対応する。クラウド保存期限・削除手段・署名検証は従来どおり。音声生成に失敗した場合も歌詞と絵を保管し、無音代替音声は実歌声として保存しない。

候補JSONは実際に存在する1～2候補だけ必須。余分な候補ファイル、署名と異なる画像・歌詞は拒否する。音声ジョブの再登録も候補数・内容が一致する場合だけ同一処理として扱う。1候補データは比較による選択を持たないため、既存の選択ベースの学習用エクスポートから自然に除外される。

## 2段生成へ戻す設定

コードと `GEMINI_VISION_MODEL=gemini-3.8-flash` / `LYRICS_BASE_MODEL=gemini-3.5-flash` を保持する。必要時は `LYRICS_PIPELINE_MODE=phase1` に変更する。A/B比較も必要ならWorkerの `LYRICS_CANDIDATE_COUNT` とブラウザの `VITE_LYRICS_CANDIDATE_COUNT` を両方 `2` にし、再ビルド・再デプロイする。画像縮小は別設定であり、`VITE_GEMINI_IMAGE_MAX_DIMENSION=0` で停止できる。これは暫定機能の復帰設定であり、公開事故時の包括的な切り戻し手順の整備は今回の対象外。

## 確認範囲と保留

自動テストは通常1段、短縮2回、上限停止、アクセント失敗、最終署名、1候補の評価・音声ジョブ、JPEG保管・再送・削除、既存A/B互換性を対象にする。品質確認コマンドは [code-quality.md](code-quality.md)。公開直後は配信版・主要API・通常1作品の生成経路を確認する。

ユーザー判断で今回は行わない項目は [BACKLOG.md](../BACKLOG.md) に集約する。弱回線・スマホ縦横の網羅検証、追加の通信軽量化、同時負荷試験、バグ報告導線、AI学習は今回の完了条件に含めない。
