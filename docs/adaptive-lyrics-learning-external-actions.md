# AI作詞の学習で外部サービスの操作が必要な項目

> 更新日: 2026-08-24
> 現在の結論: Cloudflare側の収集基盤は稼働済み。Google Cloudを使うStep 6は保留してよく、現時点で利用者が追加操作する必要はない。

この文書は、リポジトリの変更だけでは完了できず、CloudflareやGoogle Cloudの所有者による確認・承認が必要な作業をまとめる。秘密値はこの文書やGitへ書かない。

## 現在、操作しなくてよいもの

- Cloudflareの本番D1、staging用D1、Worker binding、必須Secretは設定済み。
- 本番とstagingは別Worker・別D1で分離済み。本番設定にPreview D1を置かない。
- 同意した評価だけをD1へ保存し、画像・音声・描いた線・名前・年齢・自由記述は中央保存しない。
- 認識の任意回答、聞き比べ後の最終選択、4項目の任意評価は、端末内下書きとCloudflare D1までをリポジトリ側で扱う。

## Google Cloudでの学習を再開するときに必要な本人操作

1. 使用するGoogle Cloudプロジェクトと課金アカウントを決める。
2. Geminiのチューニングに対応するサービス、モデル、リージョン、料金を、その時点の公式資料で再確認して有効にする。
3. 学習用・検証用JSONLを置く非公開GCSバケットとリージョンを決める。
4. 学習ジョブと推論だけに必要な最小権限を持つ実行主体を用意する。長期サービスアカウント鍵をGitやブラウザへ渡さない。
5. データの保存期間、削除依頼の窓口、承認担当者、学習へ進める最低件数を決める。
6. Codexへ、秘密ではないプロジェクトID、リージョン、バケットURIと、上記の運用判断だけを伝える。Secretや鍵の値は貼り付けない。

初回SFTは料金とデータ利用範囲を確認してから開始する。課金が発生するジョブの開始、権限付与、秘密値の登録は、所有者本人の確認を必須とする。

## 再開後にCodexが行えること

- D1の承認済み評価だけをJSONLへ書き出し、形式・重複・個人情報混入の候補を検査する。
- 学習用と固定評価用を分離し、データセット版と入力件数を記録する。
- 本人が確認した初回SFT手順を再現可能なスクリプトへ整理する。
- 基礎モデルと調整済みモデルを同じ条件で比較し、品質・形式成功率・速度を記録する。
- 合格したモデルだけを設定で有効化し、失敗時に基礎モデルへ戻せる切替を実装する。
- Continuous Tuningは、新しい承認済みバッチが十分にたまった場合だけ実行する。

## 本人の確認が必要になるタイミング

| タイミング | 確認・操作する内容 |
| --- | --- |
| Cloudflareの新しい課金サービスを追加するとき | 料金、保存地域、データ範囲を確認して有効化する |
| D1の評価を学習データとして承認するとき | 歌詞の品質、個人を特定し得る内容、不適切な内容を人が確認する |
| Google Cloudの準備を始めるとき | プロジェクト、課金、API、GCS、リージョン、権限を設定する |
| 初回SFT・Continuous Tuningを開始するとき | 入力データ、件数、料金見込み、パラメーターを確認して実行を承認する |
| 調整済みモデルを公開するとき | 固定評価の結果を確認し、公開版への切替を承認する |

## 共有してはいけないもの

- Gemini API key
- Cloudflare Worker Secret
- Google Cloudの秘密鍵、アクセストークン、認証JSON
- 子どもや参加者を特定できる情報
- 未確認の画像、音声、自由記述を含むデータ一式

外部サービスの画面や仕様は変わり得るため、Step 6再開時は、この文書のコマンドやモデル名を固定的に信頼せず、公式資料と現在のコンソール表示を再確認する。
