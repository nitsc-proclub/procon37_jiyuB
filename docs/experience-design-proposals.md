# 「超えかき歌！」体験デザイン案

## 方針

宇宙風の配色や背景装飾で「魔法らしさ」を足すのではなく、子どもが描いた線そのものが動き、歌へ変身し、触って遊べる体験を中心にする。

参考にしたWebデザイン事例では、画面内を探索して情報を見つける、スクロールで主役の形が変化する、操作できるミニゲームで物語が進む、扉を開けて別の空間へ入る、といった「ユーザーの行動が次の場面を生む」設計が多い。この考え方を、子どものお絵描きから歌の完成までの流れへ置き換える。

## 案1：絵が歌になる「変身シアター」

「歌をつくる」を押すと画面を別ページへ切り替えず、描いたキャンバスが舞台へ変身する。描いた順に線がもう一度現れ、その線から言葉のカードや音符が生まれる。歌が完成するとカードが歌詞の行へ整列し、そのまま再生が始まる。

- 子どもにとって、待ち時間ではなく「自分の絵が歌へ変わる瞬間」になる。
- 既存のストローク、ストロークグループ、描画再生、歌詞との対応情報を再利用できる。
- APIの実進捗を偽装せず、工程が完了したイベントだけを演出の区切りにする。
- 途中で「静かに待つ」へ切り替えられ、`prefers-reduced-motion`にも対応する。

実装難度：中。最初に作る案として最も費用対効果が高い。

## 案2：歌に合わせて絵が反応する「ライブキャンバス」

歌の再生中、現在の歌詞に対応する線だけが少し太くなる、跳ねる、描画順に光る。歌詞をタップすると、その行と対応する絵の部分へ移動し、そこから再生できる。単なる音声波形ではなく、「この言葉はこの線から生まれた」と分かる再生体験にする。

- 歌詞と絵の関係を見つける遊びになり、繰り返し再生したくなる。
- 既存の行とストロークの対応、再生位置、描画プレイバックを拡張できる。
- 音量解析が使えない場合も、歌詞の時間情報だけで成立する。

実装難度：中。変身シアターの次に実装すると資産を共有しやすい。

## 案3：自分の線をなぞる「音符あつめミニゲーム」

生成中だけ遊べる任意参加のミニゲーム。描いた線がコースになり、指やマウスで線をなぞると音符を集められる。完了率は生成処理と結び付けず、ゲームの得点としてだけ表示する。生成が終わったらいつでも結果へ進める。

- 長い生成待ちを、本人の絵を使った短い遊びへ変えられる。
- 新しいゲーム用ステージを作らず、保存済みストロークを経路として再利用できる。
- 線から大きく外れても失敗にせず、幼児でも遊べる寛容な判定にする。
- ゲームをしない選択、音なし、動きの軽減を必須にする。

実装難度：中〜高。バックエンドの所要時間に左右されない独立した体験として作る。

## 案4：描いた絵の中を歩く「発見マップ」

完成した絵を全画面の地図として拡大・移動できるようにし、ストロークのまとまりをタップすると、対応する歌詞、擬音、声が現れる。すべて見つけると最後に歌全体が再生される。通常の再生ボタンも常に残し、探索を強制しない。

- 子どもの絵自体がUIになり、毎回まったく違う画面になる。
- 「顔」「動物」などの高精度認識に依存せず、ストロークグループ単位で成立させられる。
- パン・ズーム、フォーカス移動、読み上げの設計が必要。

実装難度：高。完成後の再訪体験として試作する。

## 案5：一画面で物語が進む「スクロール変身絵本」

縦にスクロールすると、上部に固定された本人の絵が「描いた線」「言葉」「音符」「歌う絵」へ段階的に変化する。下側には各工程の短い説明と操作を置き、最後のページで通常の編集・保存・印刷へつなぐ。

- 技術説明を読ませず、変化を見るだけでAIの働きを理解できる。
- 発表会や保護者と一緒に見る場面で、作品の物語を見せやすい。
- スクロール操作が苦手な子向けに「つぎへ」ボタンを同時に提供する。

実装難度：高。結果画面の別表示モードとして検証する。

## 案6：完成の瞬間を自分で開く「うたの扉」

生成完了後、結果を自動で突然表示せず、キャンバス中央に紙の扉やカーテンを置く。子どもがドラッグして開くと、歌詞と歌声が現れる。開く前から「できた！」は伝え、ワンタップでも開けるようにする。

- 待つ工程と完成作品の間に、自分で起こす短いクライマックスが生まれる。
- 生成を遅らせず、完成済みデータの表示演出として安全に追加できる。
- 毎回長く感じないよう、2秒以内、スキップ可能、再演可能にする。

実装難度：低〜中。小さな実験としてA/B確認しやすい。

## 推奨する実装順

1. 変身シアター：既存データを最も活かし、生成待ちの中心体験を改善する。
2. ライブキャンバス：完成後の再生を「絵と歌の関係を見つける遊び」へ広げる。
3. うたの扉：完成の瞬間を短期間で強化し、子どもの反応を観察する。
4. 音符あつめ：生成時間が実際に長い環境でのみ導入する。
5. 発見マップ／スクロール変身絵本：別モードの試作として検証する。

まず1と2を一続きのプロトタイプにする。配色変更だけでは得られない「描いた行為が、歌の見え方と再生操作に残る」ことを成功条件にする。

## 実装状況（2026-07-17）

- 変身シアター：生成中のキャンバス内で実ストロークを再演し、実際の生成工程と歌詞の到着を舞台表示へ反映した。
- ライブキャンバス：再生位置に対応する線を強調し、歌詞の行を押すと対応位置から再生できるようにした。
- うたの扉：新しく生成した歌だけに短い完成演出を置き、扉を開く操作から再生を始めるようにした。
- 発見マップ／スクロール変身絵本：完成画面の切替モードとして追加し、通常再生へいつでも戻れる試作にした。

PC、幅390pxのスマートフォン、幅768pxのタブレットで主要操作と横あふれを確認した。キーボード操作、44px以上の主要タップ領域、`prefers-reduced-motion`、再生停止時の描画負荷も確認対象に含めた。

## 検証するときに見ること

- 子どもが説明なしで次の操作を見つけられるか。
- 生成待ちを長く感じるか、変身を見たいと感じるか。
- 完成後に同じ歌をもう一度再生するか。
- 自分の線と歌詞のつながりを言葉で説明できるか。
- 動き、音、文字量が刺激過多になっていないか。
- キーボード、読み上げ、動きの軽減でも同じ操作を完了できるか。
