# みんなの合奏 — ローカル展示デモ

1台のPCに保存・生成管理を集約し、同じLANの端末から利用する展示用アプリです。公開サイトとは別のエントリー、ビルド先、サーバーを使います。

## このPCで起動する

リポジトリ直下の `run-exhibition.cmd` をダブルクリックします。初回と更新後はビルドしてからサーバーが起動します。Node.js 22以上と `npm ci` 済みの環境が必要です。

PowerShellから起動する場合:

```powershell
npm.cmd run build:exhibition
npm.cmd run start:exhibition
```

| 画面 | サーバーPCでのURL | 用途 |
| --- | --- | --- |
| つくる | http://localhost:3001/ | 描画、生成、ヘッドホン試聴、歌い方変更、参加 |
| 大画面 | http://localhost:3001/stage | プロジェクター・ステレオスピーカーを接続したPCで開く |
| 演奏ボタン | http://localhost:3001/control | 子どもが使える再生・停止 |
| 保存作品 | http://localhost:3001/admin | 過去作品の再参加、保存した歌の選択、削除、音量・接続先 |

他の端末では `localhost` を、サーバー起動時に表示されるPCのIPv4アドレスに置き換えます。ポートは3001です。PCと端末を同じLANに接続し、WindowsのプライベートネットワークでNode.jsの通信を許可してください。インターネット公開やポート転送は不要です。

大画面で一度「音を有効にする」を押すと、別端末の演奏ボタンが使えます。大画面は1台だけ有効になります。「全画面」またはブラウザーの全画面表示を使えます。個人端末の試聴にはヘッドホンを使ってください。

管理用パスワードはありません。保存作品のタイルを選ぶと、生成直後と同じ詳細画面で試聴・歌い方変更・合奏への参加／退出ができます。停止はサーバーのコンソールで Ctrl+C。同じ保存先のサーバーは重複起動できません。

## デモの動作

- 標準4作品（リズム、ハーモニーのルートと5度、基本メロディー）。保存作品画面で1〜6人に設定でき、再起動後も保持します。自動生成は1人ならメロディー、2人ならリズムとメロディー、3人でルート、4人で5度、5人で3度、6人で低いメロディーを候補に加えます。
- 自動選択は参加中と生成待ちの担当を確認し、まずリズム・ルート・メロディを埋めます。同程度に空いている候補では、同じ端末で直前と別の歌い方を優先します。
- 手動では満員のパートも選べます。再生成は絵・表示歌詞を維持し、歌声の音程・リズムを担当に合わせます。以前の歌声も保存します。
- 「参加」を押した作品が同じ担当の旧作品と交代します。合奏から外れても保存作品は残ります。歌声の音程は参加時には変わりません。
- 演奏開始時のメンバーを固定し、4行×2周（約30.8秒）で停止します。演奏中の追加・交代は次回から反映し、下部の待機列に表示します。
- 1周目は薄い全体像をオレンジでなぞり、濃い線で完成します。2周目は完成した絵を残します。両方の周で現在の歌詞を表示し、進行位置を色付けします。
- 歌声と打楽器だけを大画面の単一Web Audio時計で再生します。歌声の左右位置は一列に並ぶイラストの位置に合わせます。リズム担当がいなくても合奏では打楽器を鳴らします。その他の楽器サンプルは再生・読み込みしません。
- 低いメロディーは通常のメロディーの1オクターブ下です。旧版の高い歌声は互換扱いせず、同じ作品から新しい歌声を生成します。元のWAVは保存されます。
- 人数を減らすと標準編成に合う役割を優先して残します。外れた作品は保存一覧から再参加できます。同じ役割を交代し、別役割で上限を超えた場合は参加が古い作品から外れます。演奏中の変更は次回に反映します。
- 「新しい歌を作る」で白紙へ戻ります。「中止して新しく描く」はすぐ白紙に戻り、遅れて届いた生成結果は表示・採用しません。クラウド通信は中断し、ローカルVOICEVOXは実行中リクエストが終わるまで生成枠を維持します。
- 提供されたステージ背景の上に透明な線画、歌詞の吹き出し、作品名を配置します。動きはCSS、筆順と歌詞の色付けは音声時計を使い、動きを減らすOS設定にも対応します。

125 BPM、1行8拍。コードの区切りは以下です。

| 行 | コードと拍数 |
| --- | --- |
| 1 | F（4拍）→G（4拍） |
| 2 | Em（4拍）→Am（4拍） |
| 3 | F（4拍）→G（4拍） |
| 4 | Dm（2拍）→G（2拍）→C（4拍） |

## 保存と過去作品

標準保存先は `exhibition-data/` です。`state.json` に絵・筆順・歌詞・楽譜・役割・待ち行列を、`audio/` に各生成版のWAVを保存します。日数による自動削除はありません。JSONは一時ファイルから置換し、再起動時は生成待ちを再開します。演奏中だった場合は停止状態に戻ります。

バックアップはサーバーを止めて `exhibition-data/` 全体をコピーしてください。保存先を変える場合は `EXHIBITION_DATA_DIR` を設定します。保存量は増え続けるため、会期前後にPCの空き容量を確認してください。

保存作品の「設定」→「デモ記録を読み込む」は既存の `demo-records/` の絵・筆順・4行のかな歌詞をコピーして取り込みます。元の記録には書き込みません。テンポや役割が合奏と異なる既存音声はそのまま参加させず、歌い方を選んで合奏用の歌声を生成します。読み込めない記録や4行のかな歌詞がない記録はスキップします。

## 音声とネットワーク設定

歌詞生成は既存のGemini処理・ローカル環境設定を再利用します。`.env.local` 等の `GEMINI_API_KEY` が必要です。不正な発音文字が生成された場合は、表示歌詞を変えず読み方だけを補正します。

`.env.exhibition.local` に以下を設定します。このファイルと保存作品はGit対象外です。

```dotenv
EXHIBITION_PORT=3001
EXHIBITION_VOICE_URL=https://cho-ekaki-uta-exhibition-voice.nitsc-proclub.workers.dev
EXHIBITION_TOKEN=展示専用ゲートウェイと一致する秘密値
# EXHIBITION_DATA_DIR=C:/exhibition-data
```

「自動」は未来サーバー（VPC）優先、使用中・失敗時はCloud Runを利用します。ローカルPCの生成管理は最大3処理を同時に進め、既存のバックエンド枠（VPC 1、Cloud Run 3）を共有します。空きがないときはPCに保存した待ち行列で待ちます。公開版の通常生成とも枠を共有するため、両方を同時に使うと待ち時間が増える場合があります。

予備のローカルVOICEVOXは、同じPCの `127.0.0.1:50021` で起動し、準備室で選択します。ローカル生成は直列化します。接続先を変更した後は、新規生成・「もう一度つくる」から新しい接続先を使います。試行中の生成は現在の接続先を維持します。

音声はVOICEVOX:ずんだもん。フォントはローカルビルドに含まれ、再生時の外部CDN通信は不要です。打楽器はWeb Audioで合成し、以前の楽器サンプルは配信しません。保管されている素材の出典は [assets/NOTICE.md](assets/NOTICE.md) に残しています。ステージ背景はユーザー提供の使用許可済み画像をローカルデモだけで使用しています。

## 開発・専用ゲートウェイの更新

```powershell
npm.cmd run test:exhibition
npm.cmd run type-check:exhibition
npm.cmd run build:exhibition
```

PCサーバーの変更後は再起動、画面の変更後は再ビルドとブラウザー再読み込みが必要です。楽曲仕様を変える場合は `MUSIC_VERSION` も変更し、旧楽譜を誤って同時再生させないようにします。

クラウド側は展示専用の `cho-ekaki-uta-exhibition-voice` Workerだけです。ブラウザーから秘密値を送らず、PCサーバーが認証付きで利用します。既存の音声APIと共有生成枠をService Bindingで利用し、D1に短命な音声チケットを発行・削除します。公開版のWorker・UI・Queue設定の更新は不要です。

初回の秘密値設定（このPCは設定済み）:

```powershell
node scripts/exhibition-configure.mjs
npx.cmd wrangler secret bulk .wrangler/exhibition-secrets.json --config exhibition/cloud/wrangler.jsonc
npm.cmd run deploy:exhibition-voice
```

更新時も `deploy:exhibition-voice` だけを使います。リポジトリ直下の本番デプロイは実行しません。公開サイトのビルド先 `dist/` に対して、展示のビルドは `.exhibition-build/` を使います。
